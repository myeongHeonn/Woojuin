## 0. 시스템 구성 한눈에 보기

```
                     [ 사용자 브라우저 / 크롬 익스텐션 / Wear OS 워치 ]
                                        │  HTTPS
                          ┌─────────────▼──────────────┐
                          │   호스트 Nginx (EC2, 80/443)│  ← TLS 종료 · 정적 서빙 · 리버스 프록시
                          └──┬──────────────┬──────────┘
             정적 파일 서빙   │              │  /api → 127.0.0.1:8081(prod) / 8091(dev)
      /var/www/woojuin/{env} │              │
                             ▼              ▼
                        [프론트 dist]   ┌────────────────── Docker Compose 스택 ──────────────────┐
                                        │  backend (Spring Boot, 8080)                            │
                                        │    ├── postgres (pgvector/pg16)                         │
                                        │    ├── redis (7-alpine, Redis Streams 큐)               │
                                        │    ├── minio (S3 호환 오브젝트 스토리지)                │
                                        │    ├── crawler  (FastAPI + Scrapling, 8001) ※ profile   │
                                        │    └── aimix    (FastAPI + UMAP, 8002)      ※ profile   │
                                        └─────────────────────────────────────────────────────────┘
```

- **모노레포**입니다. 한 저장소에 프론트·백엔드·익스텐션·워치앱·AI 사이드카·모니터링이 모두 들어 있습니다.
- 하나의 EC2 인스턴스에 **dev / prod 두 스택**이 Compose 프로젝트명으로 분리되어 함께 떠 있습니다.
- CI/CD는 **Jenkins Multibranch Pipeline**(`Jenkinsfile`)입니다.
  (README·AGENTS.md에 "GitLab CI"로 적힌 부분은 과거 기록이며, `.gitlab/`에는 MR 템플릿만 남아 있습니다.)

## 2. 빌드 시 사용되는 환경 변수 상세

### 2-1. 환경변수가 흘러가는 경로

```
[로컬 개발]
  레포 루트 .env  ──(springboot3-dotenv)──▶ 백엔드 프로세스
                 └─(Vite envDir:'..')────▶ 프론트 번들에 정적 치환

[CI/CD - Jenkins]
  Jenkins Secret file (env-dev / env-prod)
        │
        ├─ withCredentials → $ENV_FILE(임시 파일)
        │        └─ docker compose --env-file → backend 컨테이너 (env_file 통째 주입)
        │
  Jenkinsfile environment 블록 (VITE_FCM_*, VITE_DISCORD_APPLICATION_ID)
        └─ docker build --build-arg → 프론트 번들에 정적 치환
```

> 🔴 **Vite 변수(`VITE_*`)는 런타임이 아니라 빌드 시점에 번들에 박힙니다.**
> 그래서 dev와 prod는 **각각 따로 빌드**해야 하고, 같은 산출물을 두 환경에 복사할 수 없습니다.
> Jenkins가 프론트 이미지 태그에 `-dev` / `-prod` 접미사를 붙이는 이유입니다.

> 📌 `frontend/vite.config.ts`의 `envDir`이 **레포 루트**로 지정되어 있습니다.
> 프론트 개발 시 `.env`는 `frontend/`가 아니라 **레포 루트**에 두어야 합니다.

### 2-2. 백엔드 환경변수

각 항목의 상세 주석은 레포 루트 **`.env.example`** 에 있습니다. 아래는 분류 요약입니다.

> 📌 `.env.example` 은 **로컬 개발 기준**이라 배포 전용 키와 `DB_NAME`·`AWS_S3_*` 가 빠져 있습니다. 배포용 파일을 만들 때는 **2-6 의 템플릿**을 기준으로 하세요.

#### (a) 필수 — 없으면 기동 실패 또는 심각한 오작동

| 변수 | 용도 | 누락 시 |
| --- | --- | --- |
| `DB_URL` `DB_USERNAME` `DB_PASSWORD` `DB_NAME` | PostgreSQL 접속 | 기동 실패 |
| `REDIS_HOST` `REDIS_PORT` | Redis 접속 | 큐 처리 불가 |
| `JWT_SECRET` | JWT 서명 키 (32바이트 이상) | 레포의 개발용 기본값으로 서명 → **토큰 위조 가능** |
| `GOOGLE_OAUTH_CLIENT_ID` `GOOGLE_OAUTH_CLIENT_SECRET` | 구글 로그인 | `ClientRegistration` 검증 실패로 **기동 자체가 실패** |
| `CORS_ALLOWED_ORIGINS` | 허용 출처(쉼표 구분) | localhost로 회귀 → 브라우저 API 호출 전부 차단 |
| `OAUTH_REDIRECT_BASE_URL` | 로그인 후 리다이렉트 | localhost로 회귀 → 로그인 후 엉뚱한 곳으로 |
| `AWS_S3_BUCKET` | 버킷명 | 기본 버킷 회귀 → **dev/prod 데이터 혼입** |
| `AWS_S3_PUBLIC_ENDPOINT` | presigned URL 서명용 공개 주소 | 내부 주소로 서명 → 브라우저에서 이미지 깨짐 |
| `AWS_S3_ACCESS_KEY` `AWS_S3_SECRET_KEY` | MinIO 자격증명 | MinIO 기동 실패 |
| `CHAT_BOT_SECRET` `DISCORD_PUBLIC_KEY` `DISCORD_APPLICATION_ID` `MATTERMOST_SLASH_TOKEN` `CHAT_INTEGRATION_FRONTEND_URL` | 채팅 앱 연동 | 배포는 뜨지만 Discord 검증·Mattermost 명령 전부 실패 |

> `docker-compose.deploy.yml`은 위 값들에 `${VAR:?}` 문법을 붙여 두었습니다.
> 값이 없거나 **빈 문자열**이면 compose가 기동을 거부하므로, 오타·누락이 60초 뒤 앱 로그가 아니라 **배포 즉시** 드러납니다.

#### (b) 선택 — 없으면 해당 기능만 조용히 꺼짐 (앱 기동은 정상)

| 변수 | 기능 | 없을 때 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 텍스트 AI(검색 질의 해석), Whisper STT | 규칙 기반으로 폴백 (오타 교정 없음) |
| `OPENROUTER_API_KEY` | 이미지 VL(OCR·설명·태그), ai-mix 요약·분류·임베딩 | 이미지 텍스트 추출 꺼짐(아이템은 PARTIAL). 썸네일·EXIF·저장은 정상 |
| `KAKAO_REST_API_KEY` | 지오코딩(주소↔좌표) | 지오코딩만 꺼짐. 지도 링크·EXIF 좌표는 계속 저장 |
| `KAKAO_OAUTH_CLIENT_ID` `KAKAO_OAUTH_CLIENT_SECRET` | 카카오 로그인 | 미등록 (application.yml에 registration 미기재) |
| `FCM_PROJECT_ID` `FCM_SERVICE_ACCOUNT_KEY_BASE64` | 웹 푸시 발송 | `NoOpPushSender`로 폴백 (로그만 남김) |
| `AUDD_API_TOKEN` | 워치 노래 인식 (FR-055) | 해당 기능만 비활성 |
| `MATTERMOST_OAUTH_*` `MATTERMOST_TOKEN_ENCRYPTION_KEY` `MATTERMOST_PLUGIN_TOKEN` | Mattermost OAuth 연동 | 연동 기능 비활성 |
| `DISCORD_BOT_TOKEN` `DISCORD_GUILD_ID` | **명령 등록 스크립트 전용** | 백엔드 런타임에는 불필요 |

> ⚠️ `OPENAI_API_KEY` · `OPENROUTER_API_KEY` · `KAKAO_REST_API_KEY` 세 개는 `application.yml`의 `${VAR:기본값}`이 아니라
> **각 Config 클래스가 직접 읽습니다.** yml의 `${VAR:기본값}`은 변수가 "없을 때"만 기본값을 쓰므로
> `OPENAI_API_KEY=` 같은 빈 줄을 "키 있음"으로 오해하기 때문입니다.

| `VITE_DISCORD_APPLICATION_ID` | 마이페이지 Discord 설치 버튼 | 〃 (없으면 버튼이 조용히 사라짐) |

이 값들은 `frontend/Dockerfile`의 `ARG` → `ENV`로 받아 `npm run build` 시점에 번들에 박힙니다.
Jenkins는 빌드 후 **번들에 API 주소가 실제로 들어갔는지 grep으로 검증**합니다 —
주입에 실패해도 빌드는 성공하고 `/api` 상대경로로 폴백하기 때문입니다.

### 2-4. 크롬 익스텐션

### 2-6. 배포용 `.env` 파일 구성 (prod 기준)

앞의 2-2 는 **앱이 읽는 변수**를 기능별로 분류한 것이고, 여기는 **배포 서버에 실제로 올라가는 파일 한 장**을 그대로 옮긴 것입니다. 둘의 범위가 다릅니다.

- 위치: 운영 `~/woojuin/prod/.env.prod`, 개발 `~/woojuin/dev/.env.dev`
- 같은 파일이 Jenkins Credentials 의 Secret file `env-prod` / `env-dev` 로도 올라가 있습니다. **두 곳을 함께 고쳐야** 수동 배포와 CI 배포가 어긋나지 않습니다.

> 🔴 **`.env.example` 만 보고 배포용 파일을 만들면 기동하지 못합니다.**
> `.env.example` 은 로컬 개발 기준이라 compose 전용 키(`ENV_FILE`·`*_HOST_PORT`·`*_MEM_LIMIT`·`COMPOSE_PROFILES`·`*_IMAGE`)와 `DB_NAME`·`AWS_S3_*` 가 들어 있지 않습니다. 배포용 파일은 아래 템플릿을 기준으로 만드세요.

#### (a) `.env.prod` 템플릿

값이 비어 있는 항목이 **채워 넣어야 하는 비밀값**입니다. 값이 적힌 항목은 그대로 쓰면 되는 운영 실측치입니다.

```bash
# compose 가 자기 자신의 경로를 알아야 한다 — 수동 배포 시 필수 (4-3 참고)
ENV_FILE=/home/ubuntu/woojuin/prod/.env.prod

# ===== compose 자신을 위한 값 =====
# 호스트 포트 (dev 8091/5433/9100/9101 와 겹치면 안 됨. 8080은 Jenkins)
BACKEND_HOST_PORT=8081
POSTGRES_HOST_PORT=5432

# MinIO S3 API — nginx(minio.{DOMAIN})가 이 포트로 프록시 (presigned URL 용)
MINIO_API_HOST_PORT=9000
MINIO_CONSOLE_HOST_PORT=9001

BACKEND_IMAGE=woojuin-backend:latest
CRAWLER_IMAGE=woojuin-crawler:latest

# 자원 제한 (t2.xlarge 16GB, dev 스택·Jenkins·Gerrit 과 나눠 씀)
BACKEND_MEM_LIMIT=1500m
BACKEND_JAVA_OPTS=-Xmx1g
CRAWLER_MEM_LIMIT=2g
CRAWLER_MAX_CONCURRENCY=2
CRAWLER_SOLVE_CLOUDFLARE=true

# ===== Backend 앱 =====
DB_NAME=
DB_USERNAME=
DB_PASSWORD=

JWT_SECRET=

OPENAI_API_KEY=
OPENROUTER_API_KEY=

KAKAO_REST_API_KEY=

# 카카오 로그인 미연동 — 비워 둘 것
KAKAO_OAUTH_CLIENT_ID=
KAKAO_OAUTH_CLIENT_SECRET=

# 구글 로그인 — 비우면 백엔드가 기동하지 못한다 (아래 (e) 참고)
GOOGLE_OAUTH_CLIENT_ID=
GOOGLE_OAUTH_CLIENT_SECRET=
OAUTH_REDIRECT_BASE_URL=https://{DOMAIN}/oauth/callback

# 웹앱 + 크롬 익스텐션 두 출처. 익스텐션 ID 는 웹스토어에 등록된 자기 항목 값으로 바꿀 것
CORS_ALLOWED_ORIGINS=https://{DOMAIN},chrome-extension://<EXTENSION_ID>

# presigned URL 서명용 공개 엔드포인트 (내부 I/O 인 minio:9000 과 별개)
AWS_S3_PUBLIC_ENDPOINT=https://minio.{DOMAIN}

# MinIO (운영도 자체 호스팅)
AWS_S3_BUCKET=woojuin-items
AWS_S3_ACCESS_KEY=woojuin-prod-admin
AWS_S3_SECRET_KEY=
AWS_REGION=ap-northeast-2

FCM_PROJECT_ID=
FCM_SERVICE_ACCOUNT_KEY_BASE64=

COMPOSE_PROFILES=aimix,crawler
CRAWLER_ENABLED=true
AIMIX_ENABLED=true

# ===== 채팅 연동 (Discord / Mattermost) =====

# 봇 → 백엔드 저장 호출(X-Bot-Secret 헤더) 인증. JWT_SECRET 과 같은 이유로 dev/prod 다른 값
CHAT_BOT_SECRET=

# Discord Developer Portal > General Information
DISCORD_PUBLIC_KEY=
DISCORD_APPLICATION_ID=

# MM 슬래시 명령 저장 후 발급되는 토큰. 비어 있으면 콜백 API 가 503 으로 거부한다
MATTERMOST_SLASH_TOKEN=

# 봇이 만들어 주는 링크의 프론트 주소. 기본값이 localhost:5173 이라 안 주면
# Discord 저장 응답의 링크가 localhost 로 나간다
CHAT_INTEGRATION_FRONTEND_URL=https://{DOMAIN}

# 노래찾기 api
AUDD_API_TOKEN=
```

#### (b) 호스트 포트 — 두 스택이 한 EC2에 함께 뜬다

| 항목 | prod | dev | 비고 |
| --- | --- | --- | --- |
| `BACKEND_HOST_PORT` | `8081` | `8091` | **8080은 Jenkins가 점유** |
| `POSTGRES_HOST_PORT` | `5432` | `5433` | |
| `MINIO_API_HOST_PORT` | `9000` | `9100` | nginx `minio.{DOMAIN}` 프록시 대상 |
| `MINIO_CONSOLE_HOST_PORT` | `9001` | `9101` | 콘솔 UI |

네 개 모두 `127.0.0.1` 루프백에만 바인딩됩니다. 외부에서 직접 닿지 않고 nginx 또는 SSH 터널을 거칩니다.

> 🔴 dev/prod 가 **한 호스트를 공유**하므로 포트가 하나라도 겹치면 나중에 뜬 스택이 조용히 실패합니다. 새 환경을 추가할 때 이 표부터 확인하세요.

#### (c) 자원 제한 — 왜 이 숫자인가

인스턴스는 **t2.xlarge(16GB)** 한 대이고, 그 위에 prod 스택 · dev 스택 · Jenkins · Gerrit 이 함께 삽니다. 아래는 그 전제에서 나눠 잡은 값입니다.

| 변수 | prod 값 | 근거 |
| --- | --- | --- |
| `BACKEND_MEM_LIMIT` | `1500m` | 힙 1g + 메타스페이스·스레드 스택 여유 |
| `BACKEND_JAVA_OPTS` | `-Xmx1g` | 컨테이너의 `JAVA_OPTS` 로 매핑됨 |
| `CRAWLER_MEM_LIMIT` | `2g` | 헤드리스 브라우저가 1개당 400~500MB |
| `CRAWLER_MAX_CONCURRENCY` | `2` | 위와 같은 이유 — 올리면 `CRAWLER_MEM_LIMIT` 도 같이 올려야 함 |

`AIMIX_MEM_LIMIT` 은 파일에 없고 compose 기본값 `1g` 을 씁니다. 마찬가지로 `AIMIX_IMAGE` 도 없어 기본값 `woojuin-aimix:latest` 로 뜹니다(CI 배포 시에는 Jenkins 가 커밋 SHA 태그로 덮어씀).

#### (d) `.env` 에 **없어도** 되는 키 — compose 가 직접 넣는다

`docker-compose.deploy.yml` 의 `environment:` 블록이 아래 값들을 컨테이너 네트워크 주소로 못박습니다. `.env` 에 적어도 **무시**되므로, 로컬용 `localhost` 값이 남아 있어도 배포에 영향이 없습니다.

| 변수 | 배포 시 실제 값 |
| --- | --- |
| `DB_URL` | `jdbc:postgresql://postgres:5432/${DB_NAME}` |
| `REDIS_HOST` / `REDIS_PORT` | `redis` / `6379` |
| `AWS_S3_ENDPOINT` | `http://minio:9000` |
| `CRAWLER_BASE_URL` | `http://crawler:8001` |
| `AIMIX_BASE_URL` | `http://aimix:8002` |

> 📌 그래서 `.env.prod` 에는 `DB_URL` 이 아니라 **`DB_NAME`** 이 들어갑니다. compose 가 이 값으로 JDBC URL 을 조립합니다. `.env.example` 에는 `DB_NAME` 이 없으므로 배포용 파일을 만들 때 빠뜨리기 쉽습니다 — 빠지면 `${DB_NAME:?}` 에 걸려 기동을 거부합니다.

#### (e) 빈 값 주의 — `${VAR:?}` 는 빈 문자열도 거부한다

compose 의 `${VAR:?}` 는 변수가 **없을 때뿐 아니라 빈 문자열일 때도** 기동을 막습니다. 즉 `.env` 에 키만 적어 두고 값을 비워 두는 것은 "생략"과 같습니다.

`docker-compose.deploy.yml` 이 `:?` 로 검증하는 키는 다음과 같습니다.

`ENV_FILE` `DB_NAME` `DB_PASSWORD` `JWT_SECRET` `GOOGLE_OAUTH_CLIENT_ID` `GOOGLE_OAUTH_CLIENT_SECRET` `CORS_ALLOWED_ORIGINS` `OAUTH_REDIRECT_BASE_URL` `AWS_S3_BUCKET` `AWS_S3_PUBLIC_ENDPOINT` `CHAT_BOT_SECRET` `DISCORD_PUBLIC_KEY` `DISCORD_APPLICATION_ID` `MATTERMOST_SLASH_TOKEN` `CHAT_INTEGRATION_FRONTEND_URL` `BACKEND_IMAGE` `BACKEND_HOST_PORT` `POSTGRES_HOST_PORT` `MINIO_API_HOST_PORT` `MINIO_CONSOLE_HOST_PORT` `BACKEND_MEM_LIMIT`

> ⚠️ 위 (a) 템플릿에서 `KAKAO_OAUTH_*` 는 **정말 비워 두는 것이 맞지만**(`application.yml` 에 registration 이 없어 미연동), `GOOGLE_OAUTH_*` 는 같은 "미연동" 주석 아래에 있어도 **반드시 값이 있어야 합니다.** 운영 파일에는 채워져 있습니다.
> 값이 비면 compose 가 `required variable is missing or empty` 로 거부하고, 설령 통과하더라도 Spring 의 `ClientRegistration` 검증에서 백엔드가 기동하지 못합니다.

## 4. 배포 절차 및 특이사항

### 4-0. 서버 초기 세팅 (빈 인스턴스에서 시작할 때)

지급 인스턴스는 **EC2 t2.xlarge(16GB) 1대**뿐입니다. RDS·S3는 지급되지 않아 DB·오브젝트 스토리지까지 전부 이 안에서 돕니다.

**① 방화벽 — 22 / 80 / 443만**

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw status            # 22, 80, 443 확인
```

> 🔴 **DB(5432) · Redis(6379) · Jenkins(8080) · MinIO(9000/9001)는 절대 열지 않습니다.**
> 전부 `127.0.0.1` 루프백 바인딩이며 nginx 또는 SSH 터널로만 접근합니다. ufw에 뚫는 순간 설계가 무너집니다.
>
> ufw를 만질 때는 **SSH 세션을 2~3개 열어 두세요.** 한 세션이 막혀도 다른 세션으로 되돌릴 수 있습니다.

**② 스왑 4GB (OOM 보험)**

한 인스턴스에 prod 스택 · dev 스택 · Jenkins가 함께 뜨므로 피크에 대비합니다.

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab      # 재부팅 후 유지
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf
sudo sysctl vm.swappiness=10
free -h                    # Swap 줄에 4.0Gi
```

**③ Docker + Compose**

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker ubuntu
```

`usermod` 뒤에는 **반드시 로그아웃 후 재접속**해야 그룹이 적용됩니다. 확인:

```bash
docker run hello-world       # sudo 없이 성공해야 함
docker compose version       # v2 (compose 플러그인)
```

**④ 디렉터리**

```bash
mkdir -p ~/woojuin/prod ~/woojuin/dev    # 환경별 .env 와 compose 파일 위치
sudo mkdir -p /var/www/woojuin/prod /var/www/woojuin/dev   # 프론트 웹루트
```

**⑤ pem 키 권한 (Windows에서 접속할 때만)**

`Permissions for '...pem' are too open` 이 뜨면:

```powershell
icacls "<경로>\키파일.pem" /inheritance:r
icacls "<경로>\키파일.pem" /grant:r "$($env:USERNAME):(R)"
```

> ⚠️ **SSAFY 지급 인스턴스에는 Gerrit이 미리 설치되어 있습니다** (`/opt/gerrit`, 포트 8988/8989/29418, systemd `enabled`).
> 이번 기수는 GitLab MR을 쓰므로 **사용하지 않지만, stop·삭제하지 마세요** — SSAFY가 제공한 서비스입니다.
> 우리 스택과 포트가 겹치지 않아 그대로 두고 공존합니다. 메모리는 나눠 쓰므로 2-6 (c)의 자원 상한 계산에 이미 반영되어 있습니다.

### 4-1. 배포 대상은 브랜치가 정한다

| 브랜치 / MR 타겟 | `TARGET_ENV` | Compose 프로젝트 | 프론트 도메인 | API 도메인 | 백엔드 포트 | MinIO 포트 |
| --- | --- | --- | --- | --- | --- | --- |
| `develop` | `dev` | `woojuin-dev` | `dev.{DOMAIN}` | `api.dev.{DOMAIN}` | 8091 | 9100 |
| `main` | `prod` | `woojuin-prod` | `{DOMAIN}` | `api.{DOMAIN}` | 8081 | 9000 |

포트 값은 2026-08-09 운영 서버 nginx 설정에서 확인한 실측치입니다(6절 참고).

MR 잡은 **검증만** 하고 배포하지 않습니다. `main` 대상 MR도 검증하는 이유는, 핫픽스로 `main`이 `develop`과 갈라져 있으면 머지 결과가 처음 보는 코드이고, 프론트는 prod 값으로 **다시 빌드**되므로 prod 번들 자체가 그 MR에서 처음 검증되기 때문입니다.

### 4-2. 파이프라인 흐름

```
Checkout → Detect Changes → [변경된 파트만]
   ├─ Backend Test → Backend Build Image → AI Mix Build → Crawler Build
   │        └→ Deploy Backend (lock) → Health Check → Sidecar Health Check
   └─ Frontend Test → Frontend Build → Deploy Frontend (lock)
```

- **Detect Changes**: 모노레포라 바뀐 파트만 빌드합니다. 판단 불가 시 **전부 빌드**(fail-safe).
  내장 `when { changeset }`을 쓰지 않는 이유 — changeset은 마지막 커밋의 변경만 보므로 앞선 커밋의 변경을 놓칠 수 있습니다.
- **Deploy**: 환경별 스택은 공유 자원이라 `lock("woojuin-<env>-stack")`으로 직렬화합니다.
- **Health Check**: `docker exec`로 컨테이너가 자기 자신의 `/actuator/health`를 찌릅니다.
  호스트 포트(127.0.0.1:809x)는 Jenkins 컨테이너에서 닿지 않고, 외부 URL은 nginx가 `/actuator`를 403으로 막기 때문입니다. 5초 간격 30회 재시도.
- **post/always**: 7일 초과 dangling 이미지 및 BuildKit 캐시 정리.
  `docker system prune -a`는 **금지** — 롤백 대상 이미지와 `jenkins-docker:lts`까지 날아갑니다.

### 4-3. 배포 명령 (수동 실행 시)

```bash
docker compose -p woojuin-prod --env-file .env.prod -f docker-compose.deploy.yml up -d
docker compose -p woojuin-dev  --env-file .env.dev  -f docker-compose.deploy.yml up -d
```

수동 실행 시에는 `.env` 파일 **안에** `ENV_FILE=<자기 자신의 절대경로>` 한 줄이 있어야 합니다.
(Jenkins에서는 `withCredentials`가 `ENV_FILE` 셸 변수를 제공합니다.)

### 4-4. 배포 특이사항 (반드시 읽을 것)

**① 프론트엔드는 컨테이너로 뜨지 않습니다.**
호스트 nginx가 `/var/www/woojuin/{dev,prod}`를 직접 서빙합니다. `frontend/Dockerfile`이 만드는 이미지는 "빌드 산출물을 담아 나르는 상자"일 뿐입니다.

**② DooD 경로 함정.**
Jenkins는 컨테이너 안에 있지만 docker 명령은 **호스트 데몬**이 실행합니다. 그래서 `docker run -v $WORKSPACE:/src`는 데몬이 호스트에서 그 경로를 못 찾아 **빈 디렉터리를 마운트**합니다(에러 없이 조용히 실패). 거꾸로 호스트 경로(`/var/www/...`)는 유효하므로 프론트 배포가 그 성질을 이용합니다.

**③ 프론트 배포 시 옛 해시 애셋을 지우지 않습니다.**
배포를 가로질러 열려 있던 탭은 옛 index.html이 가리키는 옛 해시 청크를 요청합니다. 지워 버리면 lazy 페이지 이동 순간 `Failed to fetch dynamically imported module`로 크래시합니다. 대신 **mtime 7일 초과** 파일만 정리합니다.

**④ DB 스키마는 Flyway가 관리하고, Hibernate는 검증만 합니다.**
`spring.jpa.hibernate.ddl-auto=validate`이므로 엔티티와 실제 스키마가 어긋나면 **기동이 실패**합니다. 마이그레이션은 `backend/src/main/resources/db/migration/V*.sql` (현재 V1~V12, V8 결번).
`baseline-on-migrate=true` / `baseline-version=1` — 이미 테이블이 있는 DB는 V1이 적용된 것으로 간주하고 V2부터 실행합니다.

**⑤ pgvector 이미지로 처음 올릴 때 REINDEX 필수.**
기존 `postgres:16-alpine`(musl) 볼륨을 `pgvector/pgvector:pg16`(debian/glibc)으로 올리면 텍스트 정렬(collation) 구현 차이로 btree 인덱스가 조용히 틀어집니다 — 행이 있는데도 등호 조회가 0건을 반환합니다.

```bash
docker exec <postgres 컨테이너> psql -U <user> -d <db> -c "REINDEX DATABASE <db>;"
```

새 볼륨으로 시작하면 해당 없습니다.

**⑥ MinIO presigned URL은 공개 도메인으로 서명해야 합니다.**
백엔드가 presigned URL을 발급하고 브라우저가 MinIO에 직접 접근하는 구조입니다. 내부 호스트명(`minio:9000`)으로 서명하면 브라우저가 DNS 해석을 못 해 `ERR_NAME_NOT_RESOLVED`가 납니다. → `AWS_S3_PUBLIC_ENDPOINT`에 `https://minio.<env>.{DOMAIN}`를 넣습니다.
**로컬에서는 비워 둡니다**(endpoint인 localhost로 폴백 — 브라우저도 닿습니다).

**⑦ 운영도 자체 MinIO를 씁니다.**
`AWS_S3_ENDPOINT`를 비우면 백엔드가 실제 AWS S3 모드(DefaultCredentialsProvider)로 전환되는데, AWS 계정이 없어 버킷 확인 단계에서 기동이 실패합니다. compose가 `http://minio:9000`으로 하드 오버라이드합니다.

**⑧ nginx가 TLS를 종료합니다.**
`server.forward-headers-strategy=framework`가 없으면 Spring이 요청을 http로 보고 OAuth2 `redirect_uri`를 `http://...`로 잘못 생성합니다.

**⑨ CORS 설정에 웹앱 주소를 반드시 포함해야 합니다.**
코드가 localhost를 따로 더해 주지 않습니다. FE/BE가 서브도메인으로 분리되어 모든 API 호출이 CORS를 탑니다. 값이 어긋나면 브라우저가 응답을 버려 **상태코드도 남지 않습니다.**
크롬 익스텐션 출처(`chrome-extension://aifkmpjpjedlamliamnloliencimdfco`)도 함께 넣습니다 — manifest에 웹스토어 공개키를 넣어 두어 압축해제 설치본도 같은 ID를 씁니다.

**⑩ 사이드카는 compose profile 뒤에 있습니다.**
`crawler`·`aimix`는 기본 `up -d`에 포함되지 않습니다. `.env`의 `COMPOSE_PROFILES`로 환경별로 켜고 끕니다.

**⑪ 배포 중 다운타임 약 30초.**
현재는 backend 컨테이너 단순 재생성 방식입니다. Blue-Green은 nginx 전환 메커니즘 설계 후 도입 예정입니다.

**⑫ 네트워크 노출 정책.**
외부에 열린 문은 호스트 nginx(80/443)뿐입니다. postgres·minio는 `127.0.0.1` 루프백만 바인딩하고(관리 접속은 SSH 터널), redis는 호스트 바인딩이 아예 없습니다. nginx가 `/actuator` 전체를 외부에서 deny합니다.

**⑬ `.mjs` MIME 설정이 없으면 지도가 깨집니다.**
기본 `mime.types`에 `.mjs`가 없어 `application/octet-stream`으로 나가고, 브라우저의 module script MIME 검사에 걸려 maplibre-gl 워커 로드가 실패합니다(2026-07-29 실측). 6절의 `conf.d/mime-mjs.conf`가 이를 막습니다.

**⑭ 로그 로테이션.**
`json-file` 드라이버 기본값이 무제한이라 backend·crawler·aimix에 20MB × 3파일 상한을 걸었습니다. 장기 보존은 Loki(14일)가 담당합니다.

### 4-6. Jenkins 구축

Jenkins는 **호스트 docker 위의 컨테이너**로 돌고, 그 안에서 호스트 docker를 다시 조종합니다(DooD). 순서대로 따라가면 됩니다.

#### 4-6-1. 이미지 — 순정 `jenkins/jenkins:lts` 로는 안 된다

순정 이미지에는 ① `docker` CLI가 없고 ② 호스트 데몬 소켓이 없습니다. 파이프라인이 `docker build`·`docker compose up`을 해야 하므로 CLI를 얹은 이미지를 만듭니다. **데몬은 설치하지 않습니다 — CLI만 필요합니다.**

```dockerfile
# ~/jenkins-image/Dockerfile
FROM jenkins/jenkins:lts
USER root
RUN apt-get update && apt-get install -y ca-certificates curl gnupg \
 && install -m 0755 -d /etc/apt/keyrings \
 && curl -fsSL https://download.docker.com/linux/debian/gpg \
      | gpg --dearmor -o /etc/apt/keyrings/docker.gpg \
 && chmod a+r /etc/apt/keyrings/docker.gpg \
 && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
      https://download.docker.com/linux/debian $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
      > /etc/apt/sources.list.d/docker.list \
 && apt-get update \
 && apt-get install -y docker-ce-cli docker-compose-plugin docker-buildx-plugin \
 && rm -rf /var/lib/apt/lists/*
USER jenkins
```

```bash
cd ~/jenkins-image && docker build -t jenkins-docker:lts .
```

> 🔴 **`docker-buildx-plugin`을 빠뜨리지 마세요.** 없으면 레거시 빌더로 조용히 폴백하는데, 레거시 빌더는 캐시가 이미지 레이어에 얹혀 있어 커밋 SHA 태깅 + `rmi` 정리 방식이 **매 빌드 캐시를 파괴**합니다(3-3 참고).
>
> 🔴 **`USER jenkins`로 반드시 되돌리세요.** Jenkins를 root로 돌리지 않기 위한 것입니다.

#### 4-6-2. 컨테이너 기동

```bash
# docker 그룹 GID 확인 — 서버마다 다르다
getent group docker          # 예: docker:x:988:ubuntu → GID 988

docker run -d --name jenkins --restart always \
  -p 127.0.0.1:8080:8080 \
  -v /home/ubuntu/jenkins-data:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --group-add 988 \
  -e JENKINS_OPTS=--prefix=/jenkins \
  -e JAVA_OPTS=-Xmx1g \
  jenkins-docker:lts
```

| 옵션 | 이유 |
| --- | --- |
| `-p 127.0.0.1:8080:8080` | 외부 비노출. nginx `/jenkins` 프록시만 통과시킴 (6절) |
| `-v /home/ubuntu/jenkins-data:...` | **호스트 바인드**. 컨테이너를 지워도 잡·Credentials·빌드 이력이 남음 |
| `-v /var/run/docker.sock:...` | DooD의 핵심. Jenkins가 호스트 데몬의 "리모컨"이 됨 |
| `--group-add <GID>` | 소켓이 `root:docker 660`이라 **없으면 `permission denied`** |
| `JENKINS_OPTS=--prefix=/jenkins` | nginx 경로 프록시와 짝을 맞춤 |
| `JAVA_OPTS=-Xmx1g` | 한 인스턴스를 스택 2개와 나눠 씀 (4-0) |

기동 후 검증:

| 명령 | 기대 결과 |
| --- | --- |
| `docker exec jenkins docker version` | Client뿐 아니라 **Server 섹션까지** 출력 (소켓·GID 정상) |
| `docker exec jenkins docker compose version` | 버전 출력 |
| `docker exec jenkins docker ps` | **호스트의 `woojuin-*` 컨테이너가 보임** = 같은 데몬 |

> ⚠️ 기존 Jenkins를 재생성하는 경우, `docker inspect jenkins`로 **현재 env·포트·바인드·restart 정책을 먼저 복사**하세요. 하나라도 빠지면 이상하게 뜹니다.
> `jenkins/jenkins:lts` 이미지는 **지우지 마세요** — `jenkins-docker:lts`의 `FROM` 베이스입니다.

#### 4-6-3. 초기 설정 · 플러그인 · 보안

1. `https://{CI_HOST}/jenkins/` 접속 → 초기 마법사 → **admin 계정 생성** (로그인 강제)
2. 플러그인: **GitLab Branch Source**, **Docker Pipeline**, **Lockable Resources**, (선택) Mattermost
3. Jenkins 관리 > Security → **`Allow anonymous read access` 해제 확인**

> 📌 플러그인 설치 시 미러 불안정으로 dependency 에러가 나면, `$JENKINS_HOME/updates/default.json`을 삭제하고 재시작하면 카탈로그가 새로고침되면서 풀립니다.

#### 4-6-4. Credentials

| ID | 타입 | 용도 |
| --- | --- | --- |
| `env-dev` | **Secret file** | dev 환경 `.env` 파일 통째로 업로드 (2-6 구성) |
| `env-prod` | **Secret file** | prod 환경 `.env` 파일 통째로 업로드 |
| `gitlab-clone` | Username/Password (또는 SSH) | 소스 체크아웃 |
| `gitlab-pat-bs` | GitLab Personal Access Token | **Branch Source 전용.** 브랜치·MR 발견과 커밋 상태 보고 |

> 📌 변수를 10여 개씩 개별 Secret text로 등록하지 않고 **`.env` 파일 한 개**로 올립니다. `withCredentials`가 임시 파일로 풀어 주고 빌드 종료 시 삭제하며, 로그에도 찍히지 않습니다.
>
> `gitlab-pat-bs` 토큰은 **Maintainer 권한 + `api` 스코프**가 필요합니다. 그래야 "Manage Web Hooks"로 웹훅이 자동 등록됩니다.

#### 4-6-5. Multibranch Pipeline 잡

| 설정 | 값 |
| --- | --- |
| 잡 종류 | **Multibranch Pipeline** (GitLab Branch Source) |
| Discover branches — Filter by name | `develop main MR-*` |
| Discover merge requests | **Merging the MR with the current target branch revision** (머지 결과를 빌드) |
| 웹훅 | `/jenkins/gitlab-webhook/post` — 토큰이 있으면 자동 등록 |
| 상태 보고 | 플러그인이 처리 (Jenkinsfile에 보고 코드 없음) |

> 🔴 **Filter by name에 `develop`만 넣으면 MR 잡까지 걸러집니다.** `MR-*`와 `main`을 반드시 함께 넣으세요.
>
> 📌 **머지 결과를 빌드하는 것이 핵심입니다.** 소스 브랜치 끝만 빌드하면 "각자는 통과하는데 합치면 깨지는" 경우를 못 잡습니다. git은 텍스트가 겹치지 않으면 충돌로 알려주지 않기 때문입니다. 배포 이미지가 **머지 커밋 SHA**여야 하는 이유도 같습니다 — MR 브랜치 이미지를 쓰면 `develop`에 존재한 적 없는 코드를 배포하는 셈입니다.

#### 4-6-6. Jenkinsfile 밖의 안전장치 3개

파일만 봐서는 알 수 없는 전제입니다. **하나라도 풀리면 조용히 잘못 동작합니다.**

| 설정 | 위치 | 없으면 |
| --- | --- | --- |
| `Do not allow concurrent builds` | Jenkins 잡 Configure → General | 고정 태그 경쟁. 빌드 A가 만든 테스트 캐시 이미지를 B가 덮어써 **A가 B의 코드로 테스트를 통과**할 수 있음 |
| `Pipelines must succeed` | GitLab → Settings → Merge requests → Merge checks | 파이프라인이 빨간불이어도 머지 가능 |
| Lockable Resources | 플러그인 + Jenkinsfile의 `lock('woojuin-<env>-stack')` | 환경 스택은 하나뿐이라 동시 배포 시 어느 이미지가 최종인지 보장 없음 |

#### 4-6-7. GitLab CI는 쓰지 않습니다

이 레포에는 `.gitlab-ci.yml`이 **의도적으로 없습니다.** 초기에 모노레포 `rules:changes` 기반 CI가 있었으나 Jenkins로 통일하면서 제거했습니다(이중 CI 방지). Jenkinsfile의 `Detect Changes` 스테이지가 그 경로 필터 역할을 이어받았습니다.

새로 포팅하면서 GitLab CI를 쓰고 싶다면 Jenkins 쪽을 끄고 가야 합니다. **둘을 동시에 켜면** 같은 커밋에 두 파이프라인이 붙어 커밋 상태 보고가 서로 덮어쓰고, 두 배포가 같은 스택을 동시에 건드립니다.

| 파일 | 커밋 여부 | 담긴 내용 | 실제 값 보관처 |
| --- | --- | --- | --- |
| **`.env.example`** | ✅ 커밋됨 | 모든 환경변수의 **이름과 설명**. 값은 비어 있음 | — (템플릿) |

도메인·경로 일부는 환경변수가 아니라 **레포 코드에 하드코딩**되어 있습니다.
`.env`만 바꿔서는 이전되지 않으므로, 아래 파일들을 함께 수정해야 합니다.

| 파일 | 하드코딩된 값 | 비고 |
| --- | --- | --- |
| `Jenkinsfile:112` | `FRONTEND_WEBROOT = "/var/www/woojuin/${TARGET_ENV}"` | nginx의 `root` 경로와 **반드시 일치** |
| `Jenkinsfile:115` | `FRONT_HOST` — prod/dev 프론트 도메인 | 배포 후 nginx 서빙 검증에 사용 |
| `Jenkinsfile:116-117` | `FE_API_BASE_URL` — prod/dev API 주소 | 번들에 정적으로 박히고, CI가 grep으로 검증 |
| `Jenkinsfile:59-84` | `VITE_FCM_*`, `VITE_DISCORD_APPLICATION_ID` | 공개값이라 코드에 직접 기재 |
| `extension/src/api/client.ts:5-18` | 모드별 API·웹앱 주소 | `build:demo` / `build` 각각 |

> 🔴 **`FRONTEND_WEBROOT`와 nginx `root`가 어긋나면** 배포는 성공한 것처럼 보이는데 nginx가 404를 냅니다.
> Jenkins의 `Deploy Frontend` 마지막 단계가 이를 잡아내도록 nginx 서빙을 실제로 확인합니다.

> 📌 이 문서의 `{DOMAIN}`·`{CI_HOST}` 자리표시자는 **읽기 편하라고 치환한 것**이며,
> 위 파일들에는 실제 도메인 문자열이 그대로 들어 있습니다. 이전 시 함께 바꾸세요.

## 6. Nginx 설정

2026-08-09 운영 서버에서 그대로 가져온 설정입니다. 프론트는 컨테이너가 아니라 **호스트 nginx**가 서빙하므로, 이 설정 없이는 서비스가 뜨지 않습니다.

### 📌 설정에 필요한 값

아래 설정은 운영 서버에서 검증된 구조 그대로이며, 환경마다 달라지는 값만 자리표시자로 두었습니다.
**이 표의 값만 본인 환경에 맞게 정하면** 나머지는 그대로 두어도 동작합니다.

| 자리표시자 / 항목 | 의미 | 정할 때 맞춰야 할 곳 |
| --- | --- | --- |
| `{DOMAIN}` | 서비스 도메인 (예: `example.com`) | DNS A 레코드가 서버를 가리켜야 함 |
| `{CI_HOST}` | Jenkins용 호스트명 | 서버 주소 또는 SSAFY 배정 도메인 |
| 서브도메인 접두사 | `dev.` / `api.` / `api.dev.` / `minio.` / `minio.dev.` | 구조 유지 권장. 전부 DNS 등록 필요 |
| 정적 파일 경로 | `/var/www/woojuin/{prod,dev}` | `Jenkinsfile`의 `FRONTEND_WEBROOT` |
| 백엔드 포트 | prod `8081` / dev `8091` | `.env`의 `BACKEND_HOST_PORT` |
| MinIO 포트 | prod `9000` / dev `9100` | `.env`의 `MINIO_API_HOST_PORT` |

> 도메인을 하나만 쓰거나 dev 환경이 필요 없다면 해당 `server` 블록을 통째로 지우면 됩니다.
> `# managed by Certbot` 이 붙은 줄은 **직접 옮기지 말고** certbot이 새로 생성하게 두는 편이 안전합니다(아래 "설치" 참고).

### 도메인 · 포트 매핑 (실측)

| 도메인 | 대상 | 비고 |
| --- | --- | --- |
| `{DOMAIN}` | `/var/www/woojuin/prod` (정적) | SPA 폴백 |
| `dev.{DOMAIN}` | `/var/www/woojuin/dev` (정적) | SPA 폴백 |
| `api.{DOMAIN}` | `127.0.0.1:8081` | `/actuator` deny |
| `api.dev.{DOMAIN}` | `127.0.0.1:8091` | `/actuator` deny |
| `minio.{DOMAIN}` | `127.0.0.1:9000` | presigned URL |
| `minio.dev.{DOMAIN}` | `127.0.0.1:9100` | presigned URL |
| `{CI_HOST}/jenkins` | `127.0.0.1:8080` | Jenkins (SSAFY 배정 도메인) |

> Jenkins가 호스트 8080을 쓰기 때문에 백엔드가 prod 8081 / dev 8091을 쓰는 것입니다.

### TLS

Let's Encrypt(certbot) 인증서 **2장**입니다.

- `/etc/letsencrypt/live/{DOMAIN}/` — `{DOMAIN}` 및 모든 서브도메인
- `/etc/letsencrypt/live/{CI_HOST}/` — SSAFY 배정 도메인

`443 ssl` 리스너와 HTTP→HTTPS 리다이렉트 블록은 전부 certbot이 자동 생성한 것(`# managed by Certbot`)이라, 새 서버에서는 손으로 옮기지 말고 80 포트 블록만 둔 채 certbot을 실행하는 편이 안전합니다.

### 놓치기 쉬운 3가지

| 항목 | 빠뜨리면 |
| --- | --- |
| `conf.d/mime-mjs.conf` | `.mjs`가 `application/octet-stream`으로 나가 **지도(maplibre-gl) 워커 로드 실패** |
| `client_max_body_size` | 기본 1MB — 이미지 업로드가 **413**으로 실패 (API 20m / MinIO 30m) |
| MinIO의 `proxy_set_header Host $host` | presigned URL 서명에 Host가 포함돼 **SignatureDoesNotMatch** |

### 설치

```bash
# 아래 설정 파일 3개를 서버에 배치한 뒤
sudo ln -s /etc/nginx/sites-available/woojuin /etc/nginx/sites-enabled/woojuin
sudo nginx -t && sudo systemctl reload nginx

# TLS는 80 포트 블록만 둔 채 certbot을 실행하면 443 리스너가 자동으로 붙는다
sudo certbot --nginx -d {DOMAIN} -d api.{DOMAIN} -d dev.{DOMAIN} \
                     -d api.dev.{DOMAIN} -d minio.{DOMAIN} -d minio.dev.{DOMAIN}
```

`/etc/nginx/nginx.conf`는 Debian 패키지 기본값 그대로입니다. 의미 있는 부분은 아래 두 줄뿐입니다.

```nginx
include /etc/nginx/conf.d/*.conf;
include /etc/nginx/sites-enabled/*;
```

### `/etc/nginx/conf.d/mime-mjs.conf`

```nginx
# .mjs(ES module) 를 JS MIME 으로 서빙.
# 기본 mime.types 에 mjs 가 없어 application/octet-stream 으로 나가고,
# 브라우저의 module script MIME 검사에 걸려 maplibre-gl 워커 로드가 실패했다 (2026-07-29).
types {
    text/javascript mjs;
}
```

### `/etc/nginx/sites-available/woojuin`

서비스 vhost 전체입니다. `# managed by Certbot` 주석이 붙은 줄은 certbot이 자동 생성한 것입니다.

### `/etc/nginx/sites-available/default` — Jenkins 프록시

SSAFY 배정 도메인용입니다. Debian 패키지 기본 파일에서 **주석 처리된 PHP/FastCGI 예시를 걷어낸** 실사용 부분만 옮겼습니다.

```nginx
# 이름 없는 요청을 받는 기본 서버 (80)
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    root /var/www/html;
    index index.html index.htm index.nginx-debian.html;
    server_name _;

    location / {
        try_files $uri $uri/ =404;
    }
}

# {CI_HOST} (443) — Jenkins 를 /jenkins 경로로 프록시
server {
    root /var/www/html;
    index index.html index.htm index.nginx-debian.html;
    server_name {CI_HOST}; # managed by Certbot

    location / {
        try_files $uri $uri/ =404;
    }

    # Jenkins 는 호스트 8080 에서 돈다.
    # → 백엔드 컨테이너가 8080 을 못 쓰는 이유이자, prod 8081 / dev 8091 을 쓰는 이유.
    location /jenkins {
        proxy_pass              http://127.0.0.1:8080;
        proxy_set_header        Host                    $host;
        proxy_set_header        X-Real-IP               $remote_addr;
        proxy_set_header        X-Forwarded-For         $proxy_add_x_forwarded_for;
        proxy_set_header        X-Forwarded-Proto       $scheme;
        proxy_redirect          http:// https://;
        client_max_body_size 50m;
    }

    listen [::]:443 ssl ipv6only=on; # managed by Certbot
    listen 443 ssl; # managed by Certbot
    ssl_certificate /etc/letsencrypt/live/{CI_HOST}/fullchain.pem; # managed by Certbot
    ssl_certificate_key /etc/letsencrypt/live/{CI_HOST}/privkey.pem; # managed by Certbot
    include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot
}
```

> ⚠️ **`{DOMAIN}/jenkins`로는 Jenkins에 접속되지 않습니다.** SPA 폴백이 200으로 가로채 프론트 페이지가 나옵니다. Jenkins는 `{CI_HOST}/jenkins`로만 접속됩니다.

> 📌 `api.{DOMAIN}` 블록의 "presigned URL 미사용" 주석은 **낡았습니다.** 2026-07-29에 presigned URL 발급 방식으로 전환됐고(`docker-compose.deploy.yml` 참고), MinIO vhost 두 개가 바로 그 용도입니다. 설정을 옮길 때 MinIO 블록을 빼지 마세요.

## 7. 트러블슈팅

| 증상 | 원인 · 조치 |
| --- | --- |
| 기동 시 `Schema-validation: ...` 로 실패 | 엔티티와 스키마 불일치. Flyway 마이그레이션 누락 여부 확인 |
| `Unsupported Database: PostgreSQL` | `flyway-database-postgresql` 모듈 누락 (Flyway 10부터 분리) |
| `clientId cannot be empty` 로 기동 실패 | `GOOGLE_OAUTH_CLIENT_ID`/`SECRET` 누락 |
| 브라우저에서 API 호출이 **상태코드도 없이** 실패 | `CORS_ALLOWED_ORIGINS`에 실제 프론트 origin 누락 |
| 로그인 후 localhost로 리다이렉트 | `OAUTH_REDIRECT_BASE_URL` 누락 → 개발용 기본값 회귀 |
| 이미지가 `ERR_NAME_NOT_RESOLVED` | `AWS_S3_PUBLIC_ENDPOINT` 미설정 (내부 호스트명으로 서명됨) |
| 배포 후 프론트가 API를 못 찾음 | `VITE_API_BASE_URL` 주입 실패 → `/api` 상대경로 폴백. CI의 grep 검증 단계 확인 |
| 등호 조회가 행이 있는데 0건 | pgvector 이미지 전환 후 REINDEX 미실행 (collation 불일치) |
| `Connection is not available, request timed out after 30000ms` | Hikari 풀 고갈. **풀 크기를 키우는 게 답이 아님** — 점유 시간 단축이 답. `hikaricp_connections_pending` 메트릭 근거로만 조정 |
| `Apparent connection leak detected` | 30초 이상 미반납 커넥션의 진단 로그. 늦게 반납되면 `unleaked`로 정정됨 (동작 영향 없음) |
| 배포 후 사이드카가 사라짐 | `.env`의 `COMPOSE_PROFILES` 줄 누락 |
| 프론트 lazy 페이지에서 `Failed to fetch dynamically imported module` | 배포를 가로지른 오래된 탭. `vite:preloadError` 핸들러가 새로고침으로 복구 |
| `docker run -v $WORKSPACE:...` 가 빈 디렉터리 | DooD 경로 함정. 호스트 경로를 쓰거나 named volume을 쓸 것 |
| 프론트 테스트가 `Executable doesn't exist` | `package.json`의 playwright 버전과 Dockerfile 베이스 이미지 태그 불일치 |

SSAFY 15기 광주1반 공통프로젝트 S15P11C105
프로젝트가 사용하는 외부 서비스의 가입·설정·활용에 필요한 정보를 정리한 문서입니다.

> ⚠️ 이 문서에는 **실제 키·토큰·비밀번호 값을 적지 않습니다.**
> 각 서비스가 발급한 값이 들어가는 **환경변수 이름**과 **보관처**만 기재합니다.

> 환경변수의 전체 목록·설명은 레포 루트 `.env.example`에 있습니다.
>
> 📌 각 서비스에 등록하는 **Redirect URI·Endpoint URL은 우리 운영 도메인 기준**으로 적었습니다.
> 다른 환경에 올릴 때는 `{DOMAIN}` 부분만 본인 도메인으로 바꾸고 경로(`/login/oauth2/code/google` 등)는 그대로 두면 됩니다.

## 1. Google Cloud — OAuth 2.0 (구글 로그인)

| 항목 | 내용 |
| --- | --- |
| 콘솔 | https://console.cloud.google.com |
| 요금 | 무료 |
| 환경변수 | `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` |
| 값 보관처 | Jenkins Secret file `env-dev` / `env-prod` |

### 가입 및 설정 절차

1. Google Cloud Console에서 프로젝트를 생성합니다.
2. **API 및 서비스 → OAuth 동의 화면**에서 앱 이름·지원 이메일·개발자 연락처를 등록합니다.
   외부(External) 유형이면 테스트 단계에서는 테스트 사용자를 추가해야 로그인이 가능합니다.
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 웹 애플리케이션**
4. **승인된 리디렉션 URI**에 아래를 모두 등록합니다.

   | 환경 | URI |
   | --- | --- |
   | 로컬 | `http://localhost:8080/login/oauth2/code/google` |
   | dev | `https://api.dev.{DOMAIN}/login/oauth2/code/google` |
   | prod | `https://api.{DOMAIN}/login/oauth2/code/google` |

5. 발급된 클라이언트 ID·시크릿을 위 환경변수에 넣습니다.

### 요청 스코프

`openid`, `email`, `profile` (`backend/src/main/resources/application.yml`)

### ⚠️ 주의

- 이 두 값이 **비어 있으면 백엔드가 기동조차 하지 않습니다.**
  Spring Security의 `ClientRegistration` 검증이 "clientId cannot be empty"로 실패합니다.
- nginx가 TLS를 종료하므로 `server.forward-headers-strategy=framework`가 필요합니다.
  없으면 Spring이 `redirect_uri`를 `http://...`로 잘못 생성해 구글이 거부합니다.
- 크롬 익스텐션은 **자체 OAuth를 하지 않습니다.** 웹앱 로그인 화면을 열어 세션을 물려받는 방식이라
  익스텐션용 `redirect_uri`를 따로 등록할 필요가 없습니다.

## 2. Kakao Developers — OAuth (카카오 로그인)

| 항목 | 내용 |
| --- | --- |
| 콘솔 | https://developers.kakao.com |
| 요금 | 무료 |
| 환경변수 | `KAKAO_OAUTH_CLIENT_ID`, `KAKAO_OAUTH_CLIENT_SECRET` |
| 현재 상태 | ⚠️ **`application.yml`에 registration이 등록되어 있지 않습니다** |

### 가입 및 설정 절차

1. Kakao Developers에서 **내 애플리케이션 → 애플리케이션 추가**
2. **앱 설정 → 앱 키**에서 REST API 키 확인 (이것이 `KAKAO_OAUTH_CLIENT_ID`)
3. **제품 설정 → 카카오 로그인** 활성화 후 **Redirect URI** 등록
   (구글과 같은 형식: `.../login/oauth2/code/kakao`)
4. **보안** 탭에서 Client Secret 생성 → 사용함으로 설정
5. **동의 항목**에서 닉네임·이메일 등 필요한 항목을 설정합니다.

### ⚠️ 주의

- `application.yml`의 `spring.security.oauth2.client.registration`에 **kakao 블록이 없습니다.**
  빈 값인 채로 registration을 등록해두면 "clientId cannot be empty"로 부팅 자체가 실패하기 때문에,
  키를 발급받기 전까지 의도적으로 비워 둔 상태입니다.
- 카카오 로그인을 실제로 켜려면 키 발급 + `application.yml`에 registration 추가가 **둘 다** 필요합니다.

## 3. Kakao Developers — 로컬 REST API (지오코딩)

| 항목 | 내용 |
| --- | --- |
| 콘솔 | https://developers.kakao.com |
| 문서 | https://developers.kakao.com/docs/latest/ko/local/dev-guide |
| Base URL | `https://dapi.kakao.com` |
| 요금 | 무료 (일 30만 건 쿼터) |
| 환경변수 | `KAKAO_REST_API_KEY` (선택: `GEO_BASE_URL`, `GEO_TIMEOUT_MS`) |
| 타임아웃 | 3,000ms |

### 용도

주소 ↔ 좌표 변환(지오코딩)입니다. **지도 SDK가 아니라 서버 측 REST 호출**입니다.
지도 렌더링은 OpenFreeMap + MapLibre GL이 담당합니다(13번 참고).

### 발급 절차

2번(카카오 OAuth)과 **같은 카카오 앱**의 **"REST API 키"** 를 사용합니다.
단, `KAKAO_OAUTH_CLIENT_ID`와는 별개 환경변수로 관리합니다.

1. 내 애플리케이션 → 앱 설정 → 앱 키 → **REST API 키** 복사
2. 플랫폼 설정에서 서버 IP(EC2 공인 IP)를 등록해야 하는 경우가 있습니다.

### ⚠️ 주의

- 키가 없으면 **지오코딩만 꺼집니다**(`Geocoder` 인터페이스가 NoOp으로 폴백).
  지도 공유 링크에서 파싱한 좌표와 사진 EXIF에서 읽은 GPS 좌표는 계속 저장되고, 앱 기동에도 지장이 없습니다.
- 키는 `application.yml`이 아니라 `GeocoderConfig`가 **직접 읽습니다.**
  yml의 `${VAR:기본값}`은 변수가 "없을 때"만 기본값을 쓰므로 `KAKAO_REST_API_KEY=` 같은 빈 줄을 "키 있음"으로 오해하기 때문입니다.
- 타임아웃이 다른 AI 호출(8초)보다 짧은 3초인 것은 의도적입니다 —
  이 호출이 `@Transactional` 프로세서 안에서 일어나 DB 커넥션을 붙잡는 시간을 늘리기 때문입니다.

## 4. SSAFY GMS — OpenAI 호환 프록시 (텍스트 AI · STT)

| 항목 | 내용 |
| --- | --- |
| Base URL | `https://gms.ssafy.io/gmsapi/api.openai.com/v1` |
| 요금 | SSAFY 제공 (교육생 계정) |
| 환경변수 | `OPENAI_API_KEY` (선택: `AI_BASE_URL`, `AI_MODEL`, `AI_TIMEOUT_MS`, `AI_STT_MODEL`, `AI_STT_TIMEOUT_MS`) |

### 용도 및 모델

| 기능 | 모델 | 타임아웃 |
| --- | --- | --- |
| 검색 질의 해석 (오타 교정·의도 파악) | `gpt-5-mini` | 8,000ms |
| 음성 받아쓰기 (워치 음성 저장) | `whisper-1` | 20,000ms |

### 발급 절차

SSAFY GMS 포털에서 교육생 계정으로 API 키를 발급받습니다.
GMS는 OpenAI 호환 프록시이므로 **환경변수 이름만 OpenAI 것을 씁니다**(값은 GMS 키입니다).

### ⚠️ 주의

- 키가 없으면 **AI 검색이 규칙 기반으로 폴백합니다.** 앱 기동에는 지장이 없지만 오타 교정이 빠집니다.
- STT는 GMS 프록시에 **`whisper-1`만 있습니다** (`gpt-4o-transcribe` 계열 없음 — 라이브로 확인).
- `AI_BASE_URL`만 바꾸면 OpenAI 직접 호출이나 로컬 Ollama(`http://localhost:11434/v1`)로도 붙습니다.
- 키는 `application.yml`이 아니라 `AiQueryConfig`가 직접 읽습니다(3번과 같은 이유).

## 5. OpenRouter — 이미지 VL · 요약 · 분류 · 임베딩

| 항목 | 내용 |
| --- | --- |
| 콘솔 | https://openrouter.ai |
| Base URL | `https://openrouter.ai/api/v1` |
| 요금 | **종량제 (유료)** — 선불 크레딧 충전 |
| 환경변수 | `OPENROUTER_API_KEY` (선택: `VISION_BASE_URL`, `VISION_MODEL`, `VISION_TIMEOUT_MS`, `OPENROUTER_CHAT_MODEL`, `OPENROUTER_EMBEDDING_MODEL`) |

### 용도 및 모델

| 사용처 | 모델 | 타임아웃 |
| --- | --- | --- |
| 백엔드 — 이미지 분석 (OCR·설명·태그 추출) | `qwen/qwen3-vl-8b-instruct` | 20,000ms |
| ai-mix 사이드카 — 제목·요약, 카테고리 분류 | `qwen/qwen3-8b` | 45,000ms (백엔드 측) |
| ai-mix 사이드카 — 임베딩 | `openai/text-embedding-3-small` (1536차원) | 〃 |

> 4번(SSAFY GMS)과 **프로바이더·키·과금 주체가 모두 다릅니다.** 그래서 환경변수가 별도입니다.

### 가입 절차

1. https://openrouter.ai 에서 계정 생성 (Google/GitHub 로그인 가능)
2. **Credits** 메뉴에서 크레딧 충전
3. **Keys** 메뉴에서 API 키 생성
4. 키를 `OPENROUTER_API_KEY`에 넣습니다.
   백엔드와 ai-mix 컨테이너 **양쪽 모두**에 전달됩니다(compose의 `aimix` 서비스 `environment` 참고).

### ⚠️ 주의

- 키가 없으면 이미지 텍스트 추출만 꺼지고(아이템은 `PARTIAL` 상태로 저장), 썸네일·EXIF 좌표·저장은 정상 동작합니다.
- ai-mix 컨테이너는 키 없이도 뜨지만 호출이 실패하고, 백엔드는 `AiAnalyzer` 폴백(빈 결과)으로 동작합니다.
- **비용 보호 장치**: `AI_USAGE_LIMIT_ENABLED=true` + `AI_USAGE_MONTHLY_ITEM_LIMIT=500`으로
  워크스페이스 대표 OWNER 기준 **월 500개 아이템**까지만 비검색 AI 처리를 허용합니다.
- 임베딩 텍스트 포맷을 바꾸면 `AIMIX_EMBEDDING_BACKFILL=true`로 일회성 백필을 돌려야 하며,
  이후 `AIMIX_SEARCH_MAX_DISTANCE`(기본 0.7)를 재측정해 갱신해야 합니다.
- 키는 `ImageTextExtractorConfig`가 직접 읽습니다(3번과 같은 이유).

## 6. Firebase — Cloud Messaging (웹 푸시)

| 항목 | 내용 |
| --- | --- |
| 콘솔 | https://console.firebase.google.com |
| 요금 | 무료 (Spark 플랜으로 충분) |
| 백엔드 환경변수 | `FCM_PROJECT_ID`, `FCM_SERVICE_ACCOUNT_KEY_BASE64` |
| 프론트 환경변수 | `VITE_FCM_API_KEY`, `VITE_FCM_AUTH_DOMAIN`, `VITE_FCM_PROJECT_ID`, `VITE_FCM_STORAGE_BUCKET`, `VITE_FCM_MESSAGING_SENDER_ID`, `VITE_FCM_APP_ID`, `VITE_FCM_VAPID_KEY` |

### 가입 및 설정 절차

**① 프로젝트 생성**
Firebase 콘솔에서 프로젝트를 생성합니다. dev와 prod가 **같은 Firebase 프로젝트**를 공유합니다.

**② 웹 앱 등록 (프론트엔드용 — 공개값)**
프로젝트 설정 → 일반 → 내 앱 → 웹 앱 추가 → 표시되는 설정 객체의 값을 `VITE_FCM_*`에 넣습니다.
이 값들은 **클라이언트 번들에 그대로 노출되는 공개값**이라 `Jenkinsfile`의 `environment` 블록에 직접 기재되어 있습니다.

**③ VAPID 키 (프론트엔드용 — 공개값)**
프로젝트 설정 → 클라우드 메시징 → 웹 구성 → **웹 푸시 인증서**에서 키 쌍을 생성하고,
공개키를 `VITE_FCM_VAPID_KEY`에 넣습니다.

**④ 서비스 계정 키 (백엔드용 — 🔴 비밀값)**
프로젝트 설정 → 서비스 계정 → **새 비공개 키 생성**으로 JSON 파일을 받습니다.
원본 JSON은 개행이 있어 `.env`에 그대로 넣을 수 없으므로 **base64 한 줄로 인코딩**해서 넣습니다.

```bash
# macOS / Linux
base64 -i service-account.json | tr -d '\n'
```

```powershell
# Windows (PowerShell)
[Convert]::ToBase64String([IO.File]::ReadAllBytes("service-account.json"))
```

### ⚠️ 주의

- `FCM_SERVICE_ACCOUNT_KEY_BASE64`는 이 프로젝트 프론트/백엔드 통틀어 **유일한 Firebase 비밀값**입니다.
  Jenkins Secret file(`env-dev`/`env-prod`)에만 두고, `firebase-adminsdk*.json` 원본은 **절대 커밋하지 않습니다.**
- 키가 없으면 `NoOpPushSender`로 폴백해 로그만 남기고 실제 발송은 생략됩니다.
- **알림 정책**: AI 처리가 `DONE` 또는 `PARTIAL`이면 푸시를 보내고 `FAILED`면 생략합니다.
  알림을 거부한 사용자를 위해 상태 조회 API(`GET /items/{id}/status`)가 폴백으로 존재합니다.
- 서비스워커는 `frontend/src/sw.ts` (vite-plugin-pwa `injectManifest` 전략)입니다.

## 7. AWS — EC2 (인프라)

| 항목 | 내용 |
| --- | --- |
| 콘솔 | https://console.aws.amazon.com |
| 리전 | `ap-northeast-2` (서울) |
| 환경변수 | `AWS_REGION` |

### 사용 범위

| 서비스 | 사용 여부 | 비고 |
| --- | --- | --- |
| **EC2** | ✅ 사용 | 단일 인스턴스에 dev·prod 스택 + Jenkins 모두 호스팅 |
| **S3** | ❌ **미사용** | 자체 호스팅 **MinIO**(S3 호환)로 대체 (아래 참고) |
| **RDS** | ❌ 미사용 | PostgreSQL도 컨테이너로 직접 운영 |

### MinIO (S3 호환 오브젝트 스토리지)

AWS S3 대신 **컨테이너로 직접 운영하는 MinIO**를 씁니다. AWS SDK for S3를 그대로 사용하되 엔드포인트만 MinIO로 향합니다.

| 환경변수 | 로컬 | 배포 |
| --- | --- | --- |
| `AWS_S3_BUCKET` | `woojuin-items` | 환경별로 다르게 (dev/prod 데이터 혼입 방지) |
| `AWS_S3_ENDPOINT` | `http://localhost:9000` | compose가 `http://minio:9000`으로 하드 오버라이드 |
| `AWS_S3_PUBLIC_ENDPOINT` | **비워 둠** | `https://minio.<env>.{DOMAIN}` |
| `AWS_S3_ACCESS_KEY` / `AWS_S3_SECRET_KEY` | 로컬 기본값 | Jenkins Secret file |

### ⚠️ 주의

- `AWS_S3_ENDPOINT`를 **비우면** 백엔드가 실제 AWS S3 모드(`DefaultCredentialsProvider`)로 전환됩니다.
  AWS 계정이 없어 버킷 확인 단계에서 **기동이 실패**합니다.
- `AWS_S3_PUBLIC_ENDPOINT`는 presigned URL **서명용 공개 주소**입니다.
  내부 호스트명(`minio:9000`)으로 서명하면 브라우저가 DNS 해석을 못 해 `ERR_NAME_NOT_RESOLVED`가 납니다.
- 보안 그룹은 **80/443/22만** 열고, 나머지 서비스는 `127.0.0.1` 루프백 바인딩 + SSH 터널로 접근합니다.

| 항목 | 내용 |

| 스크립트 전용 | `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID` (백엔드 런타임에는 불필요) |
| 프론트 환경변수 | `VITE_DISCORD_APPLICATION_ID` (설치 링크의 client_id — 공개값) |

### 가입 및 설정 절차

1. Discord Developer Portal에서 **New Application** 생성
2. **General Information → Public Key** 값을 `DISCORD_PUBLIC_KEY`에 넣습니다 (요청 서명 검증용).
   같은 화면의 Application ID를 `DISCORD_APPLICATION_ID`와 `VITE_DISCORD_APPLICATION_ID`에 넣습니다.
3. **Installation** 에서 **Guild Install**과 **User Install**을 모두 활성화합니다.
4. 기본 설치 범위에 **`applications.commands`** 를 포함합니다.
   Gateway 이벤트를 받지 않으므로 **Privileged Gateway Intents는 켜지 않습니다.**
5. **Interactions Endpoint URL**을 아래로 저장합니다.

   | 환경 | URL |
   | --- | --- |
   | prod | `https://api.{DOMAIN}/api/integrations/discord/interactions` |
   | dev | `https://api.dev.{DOMAIN}/api/integrations/discord/interactions` |

   > 저장 시 Discord가 즉시 검증 요청을 보내므로, **백엔드가 먼저 떠 있어야** 저장에 성공합니다.

6. **Bot** 탭에서 토큰을 발급해 `DISCORD_BOT_TOKEN`에 넣습니다(명령 등록 스크립트에서만 사용).
7. 슬래시 명령을 등록합니다.

   ```powershell
   cd backend
   .\scripts\register-discord-command.ps1     # 등록 (PUT bulk overwrite)
   .\scripts\list-discord-command.ps1         # 확인 (읽기 전용, 토큰 미노출)
   ```

   - `DISCORD_GUILD_ID`를 **비우면 전역 등록**(반영에 시간이 걸림), 넣으면 해당 테스트 서버에 즉시 반영됩니다.
   - 운영 명령은 `DISCORD_GUILD_ID`를 비운 뒤 전역 등록합니다.

### 사용자 이용 범위

- **사용자 설치**: 사용자가 우주인 마이페이지의 설치 버튼으로 자기 Discord 계정에 한 번 설치하면
  Discord가 허용하는 서버·DM에서 슬래시 명령과 `앱 → 우주인에 저장`을 사용할 수 있습니다.
- **서버 설치**: 서버 관리자가 서버에 한 번 설치하면 구성원들이 사용할 수 있습니다(채널마다 설치하지 않음).
- 어느 방식이든 각 우주인 사용자는 **연결 코드를 통한 최초 1회 계정 연결**이 필요합니다.
- 서버 정책에서 외부 앱 사용이 막혀 있으면 사용자 설치 앱이 보이지 않을 수 있습니다.

### ⚠️ 주의

- **앱 재설치 ≠ 명령 갱신.** 명령 구조를 바꿨다면(`backend/scripts/discord-command.json` 수정)
  반드시 등록 스크립트를 다시 실행해야 합니다. 스크립트는 `PUT`(bulk overwrite)이라 옛 잔여 서브커맨드도 함께 제거됩니다.
- Discord에서는 `workspace` 변경을 위치 인자(`/woojuin workspace 3`)로 입력할 수 없습니다.
  자동완성에서 `/woojuin workspace`를 고른 뒤 `number` 옵션에 번호를 넣어야 합니다.
- dev와 prod가 **같은 Discord 앱을 공유**합니다.

## 9. Mattermost — 채팅 연동

| 항목 | 내용 |
| --- | --- |
| 요금 | 자체 호스팅 (SSAFY 제공 인스턴스) |
| 환경변수 | `MATTERMOST_SLASH_TOKEN`, `MATTERMOST_SERVER_URL`, `MATTERMOST_OAUTH_CLIENT_ID`, `MATTERMOST_OAUTH_CLIENT_SECRET`, `MATTERMOST_OAUTH_REDIRECT_URI`, `MATTERMOST_OAUTH_FRONTEND_REDIRECT`, `MATTERMOST_TOKEN_ENCRYPTION_KEY`, `MATTERMOST_PLUGIN_TOKEN` |

### 슬래시 명령 설정 (통합 → 슬래시 명령 → 추가)

| 항목 | 운영 값 |
| --- | --- |
| 트리거 | `woojuin` |
| 요청 URL | `https://api.{DOMAIN}/api/integrations/mattermost/commands` |
| 요청 메서드 | `POST` |
| 응답 사용자명 | `woojuin` |
| 응답 아이콘 | `https://{DOMAIN}/icons/icon-512.png` |
| 자동완성 제안 | `우주인에 링크와 메모를 저장하고 저장한 정보를 검색합니다` |
| 자동완성 설명 | `[save <URL 또는 메모> \| search <검색어> \| workspace <list/번호> \| connect <코드>]` |

명령을 저장하면 Mattermost가 토큰을 발급합니다. 이 값을 `MATTERMOST_SLASH_TOKEN`에 넣습니다.

### OAuth 앱 설정 (시스템 콘솔 → 통합 → OAuth 2.0 애플리케이션)

- 콜백 URL: `https://api.{DOMAIN}/api/integrations/mattermost/oauth/callback`
  (로컬은 터널 주소: `https://<tunnel>/api/integrations/mattermost/oauth/callback`)
- 발급된 Client ID / Secret을 `MATTERMOST_OAUTH_CLIENT_ID` / `MATTERMOST_OAUTH_CLIENT_SECRET`에 넣습니다.
- `MATTERMOST_SERVER_URL`은 **로컬 PC 주소가 아니라 Mattermost 사용자가 접속하는 서버 origin**입니다.
- `MATTERMOST_TOKEN_ENCRYPTION_KEY`는 OAuth 토큰을 DB에 암호화 저장하는 키입니다.
  운영에서는 32바이트 이상 랜덤값을 쓰고, **변경하면 기존 사용자가 재연결해야 합니다.**
- `MATTERMOST_PLUGIN_TOKEN`은 Mattermost 플러그인과 우주인 API가 공유하는 별도 랜덤값입니다.

### 이용 범위

- `/woojuin` 슬래시 명령은 **채널이 아니라 Mattermost 팀 단위**로 등록됩니다.
  한 팀에 한 번 등록하면 그 팀의 공개·비공개 채널에서 별도 설치 없이 사용할 수 있습니다.
- 다른 팀에서는 그 팀 관리자가 별도로 등록해야 합니다.
- 현재 설정은 `MATTERMOST_SLASH_TOKEN` 하나를 검증하므로 **하나의 팀 등록**을 지원합니다.
  여러 팀을 동시에 지원하려면 설치 토큰을 DB에서 관리하는 후속 기능이 필요합니다.

### ⚠️ 주의

- 요청 URL에 OAuth callback URL을 잘못 넣으면 `405 Method Not Allowed`가 발생합니다.
- `MATTERMOST_SLASH_TOKEN`이 비어 있으면 콜백 API가 **503**으로 거부합니다.

## 15. 신규 환경 구축 시 최소 발급 목록

새 팀·새 환경에서 프로젝트를 띄울 때 **반드시** 발급해야 하는 것:

| 순위 | 서비스 | 이유 |
| --- | --- | --- |

해당 기능만 조용히 비활성화되므로 단계적으로 붙일 수 있습니다.

로컬 개발만 할 경우에는 **Google OAuth 하나만** 있으면 됩니다 —
DB·Redis·MinIO는 `docker compose up -d`가 로컬 기본 자격증명으로 띄워 줍니다.
